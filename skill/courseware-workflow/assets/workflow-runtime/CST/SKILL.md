# 网页课件 Skill

> 版本：4.9
> 用途：定义 Lab 单页 HTML 课件的核心设计、交互、审查和交付规则。
> 内容字段见 `CONTENT.md`，实现与组件代码见 `TEMPLATE.html`。

## 0 文件契约

| 文件 | 负责 | 不负责 |
| --- | --- | --- |
| `live.json.deck` | 课程数据、逐屏配置、交互实例、来源和页面级 CSS | 脚本、最终 DOM |
| `SKILL.md` | 设计规则、交互原则、审查和验收 | 具体课程文案 |
| `TEMPLATE.html` | 主题、屏型、组件和运行时 | 课程数据和验收报告 |
| 交付 Markdown | 页面矩阵、交互索引、来源和验收证据 | 重新定义正文 |
| 交付 HTML | 实际渲染、DOM 和交互 | 规范真源 |

规则：

1. Builder 只填槽，不临时发明新结构。
2. 新组件先更新模板与契约，再进入页面内容。
3. 课件主题固定为 Lab。
4. 不允许远程字体、CDN 或在线运行时。
5. 全局 CSS 只保存通用规则；页面专属 CSS 写入 `live.json.deck.style_overrides`。

## 1 页面与信息层级

- 舞台为 `1920 × 1080`，整体等比缩放。
- 每屏一个不嵌套的 `section.slide`。
- 页面标题 68px，长标题可降为 58px。
- 默认字体令牌以基本算法最终 HTML 为准：
  - `--serif: "Noto Serif SC", "Songti SC", serif`
  - `--sans: "MiSans", "Noto Sans SC", "Microsoft YaHei", "PingFang SC", sans-serif`
  - `--mono: "Cascadia Mono", "SFMono-Regular", Consolas, monospace`
  - `--font-scale: 1.08`
- 封面和页标题使用 `--serif`，正文使用 `--sans`，数据与控制使用 `--mono`。
- 表格字号写在 `td` / `th` 上，不写裸字号。
- `.body-area` 和 `.wx-body` 的直接子块使用固定 `18px` 垂直间距。
- 默认卡片圆角 16px、Lab 卡片 8px、Lab 面板 14px。

## 2 文本与双语

- 中文默认，英文完整切换。
- 标题、眉标、导语、注释和导航必须同步切换。
- 中文与英文表达同一事实，不能只翻译关键词。
- 一屏只表达一个主要判断。
- 关键结论、表格和交互初值在无 JS 时必须可读。
- 事实与推断分开；推断必须有明确标识。

## 3 配色与构图

| 角色 | Lab 令牌 |
| --- | --- |
| 交互强调 | `--amber: #066B5B` |
| 正确状态 | `--mint: #087A63` |
| 风险状态 | `--coral` |
| 数据对照 | `--cyan` |
| 辅助分类 | `--violet` |
| 交互面板 | `--glass*` |

规则：

- 禁止用白色背景表示交互选中。
- 默认、悬停、选中和交互后保持灰色毛玻璃。
- 状态不能只靠颜色，必须结合文字、边框或形状。
- 新增颜色必须说明语义和对比度。

## 4 八种屏型

| 屏型 | 用途 |
| --- | --- |
| `screen-cover` | 封面 + 视觉 |
| `screen-text` | 单栏正文 |
| `screen-split` | 双栏图文 |
| `screen-table` | 表格主导 |
| `screen-figure` | 图形或多控件实验台 |
| `screen-widget` | 单个标准交互面板 |
| `screen-summary` | 链条、卡片或总结 |
| `screen-quiz` | 练习与自测 |

双栏两列都必须有内容。`screen-widget` 和 `screen-quiz` 的外壳已提供交互根，
主体内不得嵌套同类型根。

## 5 动效与静态降级

- 入场动画只表达出现顺序，不承载必要信息。
- 所有内容在 1.8s 内完成落位。
- 尊重 `prefers-reduced-motion`。
- 自动演示默认关闭，除非是明确允许的视觉辅助。
- 循环动画仅用于时间、数据流、脉冲等功能语义。
- 首屏、正文、表格、结论和静态初值在无 JS 时完整可读。

## 6 交互组件

注册方式：`CW.define(name, build)`。

内置组件键：

```text
bits · quiz · slider · table · svg · algo · three
```

组合交互族包括：

```text
chart · flow · terminal · neural-network · linked-lab
```

每个交互根：

- 必须有唯一 `data-iw-id`。
- 不得嵌套在另一个 `data-iw` 内。
- 必须有可读标签和键盘操作。
- 至少联动两个表示：数值、图形、文字或状态。
- 必须有静态初值和复位方式。
- 自动播放必须可暂停。
- 每个交互屏至少包含两个用户可操作控件，以及至少两个 `linked_components`，
  写入同一 `linked_state`。
- 任一联动组件变化后，其他组件至少有一个可见表示同步更新。
- 单一控件独占整屏且无联动读数、图形、表格或过程的交互屏不合格。
- 图表分析使用 chart 族：选择指标、范围或场景后，图形、表格读数和解释同步变化。

### 6.1 复杂交互选型 Gate

新增或返工的复杂交互必须先：

1. 在网上检索真实、可访问的同类案例。
2. 用户提供的 HTML 可作为其中一个候选。
3. 合并近似方案，最多保留 3 个。
4. 每个候选记录来源、机制、优点、限制、适配性和本地 HTML 预览。
5. 在对话界面中展示效果预览和原网站 URL。
6. 用户选定后才能实现。

### 6.2 统一实验台结构

- 顶部：预设、参数、模式和播放控制。
- 中部：主视图与当前状态。
- 侧边或下方：至少两个联动读数。
- 底部：不变量、公式或结论。
- 自动播放默认关闭，播放按钮使用 `aria-pressed`。

### 6.3 交互覆盖

- 至少 70% 屏幕有可操作或可观察状态变化。
- 课件至少有一个交互表格和一个交互 SVG。
- 每个操作必须改变数值、图形、说明或系统状态。
- 每个交互屏必须至少有两个联动组件，例如“滑块 + SVG + 表格 + 算法轨迹”。
- 多控件实验台使用 `screen-figure`。
- 表格交互使用一层 `.ix-table-wrap` 外框；`.table-scroll` 与 `.ix-detail`
  作为内部双区共享圆角，中间只用分隔线，不再各自绘制独立外框。
- 物理硬件 3D 使用 `three`；二维关系默认不得强套透视。
- 用户明确选择 3D 关系网络时，可使用 `data-three-scene="workflow-network"`：
  场景不得添加 Ambient、Directional 或 Point Light；节点球体使用
  `MeshBasicMaterial` 平涂固有色，依靠空间位置、透视和连线表达三维关系。
  连线必须有方向；交互必须支持指针拖拽旋转、滚轮缩放、键盘方向键、复位、
  可暂停的自动环绕与减少动态效果处理。
- 分层网络等需要保持主阅读方向的三维场景，可在交互根声明
  `data-network-orbit-range="0.32"`，让自动环绕在有限角度内往复；拖拽、缩放、
  键盘控制和复位仍保持可用，避免侧视时所有层压成一根纵列。
- 分层 3D 网络的文件与层标签应放在画布外的固定 HTML 标签带中；中英文切换时，
  状态提示与 canvas `aria-label` 必须同步刷新。

### 6.4 算法轨迹一致性

- 每一步必须以上一步的输出为输入，不得跳步或重复旧状态。
- 排序轨迹要写明当前轮次、未排序区和比较边界。
- 未排序区应按算法定义逐步缩短；若某轮没有交换，终止条件必须与轮次记录一致。
- Reviewer 必须抽样核对首轮、中间轮和最后一轮，而不是只检查末态有序。

### 6.5 终端与滚动面板

用于模拟终端、日志、代码输出或长列表的交互必须把所有可变高度内容限制在一个
明确的“屏幕”内：

- 外层使用 `data-terminal-pane`，并设置 `min-height:0`、`max-height:100%`、
  `overflow:hidden`。
- 可变内容使用 `data-terminal-scroll`，并设置
  `min-height:0`、`overflow-y:auto`、`overscroll-behavior:contain`。
- 输入栏、执行按钮和必要控制使用 `data-terminal-fixed`，不得随输出向下移动。
- 自动追加内容后滚到最新一行，但最新一行不得把输入栏推出面板。
- 连续执行大量命令时，只允许内部滚动条增长，不得扩大幻灯片安全区。
- 浏览器验收必须至少注入 30 次输出，并核对输入栏仍位于面板和舞台内。

## 7 图形与流程

- 二维图使用内联 SVG。
- 内容图必须有 `role="img"` 和可访问名称；使用 `aria-label` 命名，并用
  `<desc>` 提供说明。交互图不得使用会在鼠标悬停时弹出原生提示框的 `<title>`。
- 电路走线正交，端点落在端口。
- 活动图必须包含开始、动作、判断、合并和终止。
- 分支标签写明互斥条件，箭头落到下一节点边界。

流程图高亮：

- 任一时刻只允许一个 `[data-flow-node]` 处于 `.is-on`。
- 点击、`Enter` 或 `Space` 切换当前节点。
- 高亮同步更新 `[data-flow-title]` 和 `[data-flow-detail]`。
- 中英文切换后保留当前节点。
- 高亮表示流程位置，不得只用颜色作为唯一载体。
- 数据元素状态切换保持瞬时，不使用位移动画或发光描边。
- 需要“仅填充、无描边”效果时，在交互根添加
  `data-flow-highlight="single-fill"`，该标记必须由浏览器检查验证。
- 教材类交互 SVG 默认使用 `data-flow-highlight="single-fill"`。
- 选中状态只能填充节点自身已经绘制的几何区域；不得出现额外状态框、描边、
  发光、阴影、位移或覆盖整个文本容器的透明点击热区。
- 未选中节点同样使用填充区分边界，不保留黑色或深色轮廓描边；连接线只存在于
  节点之外，不得沿节点周围绘制线稿。
- 指针命中范围由可见图形与文字本身的并集组成，使用
  `pointer-events:visiblePainted`；不得用透明矩形扩大热区。
- 选中填充固定为荧光黄绿 `#EFFF54`，文字保持深色。颜色之外还要同步右侧标题与说明。
- 时间线里程碑必须使用矩形、多边形或其他带填充的几何图形；不得只用空心圆或
  线框圈表示时间节点。线条只承担连接关系，不承担选中状态。

### 7.0 图表类型与结构图

先判断读者任务，再决定图表：

| 读者任务 | 图表 |
| --- | --- |
| 理解原理 | 分层块图、概念流程图、局部放大的示意结构 |
| 调试实现 | 与实际模型一致的节点/边拓扑，含算子、shape 和输入输出 |
| 论文/展示 | 参数化矢量块图，统一节点、标签、尺寸和配色 |
| 比较结构 | 同尺度并排图或表格 |
| 数值趋势 | 折线、柱形、散点等标准统计图 |

判断顺序：

1. 邻接/连接是否是答案？否 → 流程图、块图、时间轴或统计图。
2. 是否同时需要模块层级、张量维度或数据流？是 → 架构图。
3. 架构是否属于神经网络？是 → 进入 MLP、CNN、RNN、Transformer 或 GNN 专用分支。
4. 用途是理解原理、调试实现还是论文展示？据此决定抽象程度和保真度。

神经网络结构图规则：

- MLP 用分层节点/块表示输入、隐藏和输出；CNN 用层块、卷积核、池化和尺寸变化；
  RNN 展开时间步并标出循环与门控；Transformer 用模块、残差分支和注意力/前馈子层。
- 主模块通常 5–7 个；更多细节使用“总览 → 选择模块 → 局部展开”。
- 不绘制全部神经元；示意节点数可以少于真实规模，但必须明确标注。
- 每层标明角色，关键层标明张量 shape；所有连接有方向，分支与合并标注条件。
- 系统模块、层、算子和单个神经元不得混在同一粒度。
- 2D 是默认；只有深度、体积或空间关系本身重要时使用 3D。
- 优先直接标注，避免依赖图例；颜色不能是唯一编码。
- 避免全连接“毛线球”，使用束线、聚合节点、分组或局部放大。

结构图提示词采用四段式：

1. 主体：具体模型或模块。
2. 顺序：输入 → 层/模块 → 输出。
3. 标注：模块名、张量维度、重复次数、分支和共享参数。
4. 风格与方向：扁平技术示意、短标签、左到右或上到下。

重复结构折叠为 `×N`；图内只保留短标签，解释放图注。使用增量修改，不重写整图。
输入、逐层 shape 和输出 shape 必须连续。标签拥挤时拆为总览与局部图。

来源用于设计判断：
[NN-SVG](https://doi.org/10.21105/joss.00747)、
[Netron](https://github.com/lutzroeder/netron)、
[PlotNeuralNet](https://github.com/HarisIqbal88/PlotNeuralNet)、
[SciDraw 架构图指南](https://sci-draw.com/zh/blog/ai-architecture-neural-network-diagram-guide)、
[SciDraw 结构图提示词](https://sci-draw.com/zh/blog/neural-network-diagram-prompts)。

### 7.1 文字概念页：批注式讲义

用于定义、原理、辨析、验证和程序设计迁移等文本主导页面。文字概念页不得套用
五张等宽卡片的通用摘要模板；应使用“主线正文 + 页边索引 + 例题侧栏”的批注式
讲义结构，让大段文字保持连续阅读，同时把例子和误区放在可扫读的位置。

版式契约：

| 区域 | 宽度与层级 | 内容职责 |
| --- | --- | --- |
| 页边索引 | `230px`，17–18px | 2–4 个概念标记或推导步骤，说明当前页的阅读路径 |
| 主线正文 | 自适应剩余宽度 | 一个核心判断、两段解释；正文 24–26px，行高约 1.65 |
| 例题侧栏 | `390px`，正文 19–21px | 一个具体例子和一个常见误区；不得复制主线结论 |
| 迁移带 | 底部横跨主线 | 一句“程序设计迁移 / Programming Transfer”，说明如何转化为代码、测试或模块设计 |

构图规则：

1. 每屏只保留一个主标题和一个核心判断，避免标题与正文重复。
2. 主线正文优先使用连续段落；段间以留白、细分隔线或短标签建立层级，不用密集卡片包围每句话。
3. 页边索引只承担导航和提示，不重复正文整句。英文代码列使用
   `minmax(112px, max-content)`，中文说明列使用 `minmax(0, 1fr)`，两列间距
   10–12px；`ALGORITHM`、`REPRESENTATION` 等长标签不得压到中文说明。
4. 例题侧栏必须给出可代入的小例子或检查问题；误区侧栏必须指出错误模型及修正方向。
5. 中英文正文必须成对出现，英文不是关键词拼贴；语言切换后各区域结构保持稳定。
6. 固定 1920×1080 舞台内检查三栏基线、正文末行和底部迁移带，不得出现最末一行被截断或侧栏遮挡。

推荐类名：

```text
.concept-annotated
.concept-layout-b
.concept-margin-index
.concept-main-copy
.concept-example-rail
.concept-transfer-band
```

页面级 CSS 必须限定在 `.concept-annotated` 下。仅当正文确实需要超过两段时，
可增加同结构的连续段落，不得回退为五等分卡片；需要并列对照数据时改用表格页。

#### 7.1.1 重点句荧光笔标记

荧光笔用于强调当前概念页的关键判断、前提或思维动作，不得把整段正文涂满。
每页最多两处；优先选择包含完整判断的短句，中文单处通常不超过 22 个字符。
中英文可以使用不同长度的对应短语，但必须表达同一重点，不能只抽取零散关键词。

视觉与动效契约：

| 项目 | 规则 |
| --- | --- |
| 标记类名 | `.hl-mark`；第二处加 `.hl-delay-2`，需要第三处时加 `.hl-delay-3` |
| 颜色 | 荧光黄绿 `#DDFF50` 到 `#AEE037` 的斜向渐层，正文墨色保持不变 |
| 覆盖范围 | 只覆盖字面下方约 60% 高度，不改变行高和文字位置 |
| 划入方向 | 背景宽度从 0 扫到 100%，仅随当前 `.slide.on` 播放 |
| 时长 | `0.82s`；首处延迟 `0.28s`，第二处 `0.52s`，第三处 `0.74s` |
| 降级 | `prefers-reduced-motion` 与打印模式直接显示完整标记 |

实现约束：

1. 高亮背景必须写在 `.hl-mark` 自身的 `background-image` 和 `background-size`
   上，文字位于同一元素的正常前景层；不得使用负 `z-index` 伪元素把颜色压到页面背景后方。
2. 标记元素使用 `display:inline-block` 与 `white-space:nowrap`，保证颜色盒与文字盒
   共用同一边界；不得用绝对定位坐标手工猜测文字位置。
3. 标记不应带发光、描边、位移动画或白底选中态，避免与算法交互状态混淆。
4. 页面选择器写成 `.concept-annotated.slide.on .hl-mark`；不得写成
   `.concept-annotated .slide.on`，因为 `.slide` 与 `.concept-annotated` 是同一元素。

浏览器验收必须同时检查中文和英文模式：

1. 每个可见标记的 `getClientRects().length === 1`，不得换行或拆成多个色块。
2. 标记完全位于所属 `p` 的可见矩形内，且 `p.scrollWidth <= p.clientWidth + 2`。
3. 同页两个标记矩形不得相交；标记高度不得超过所属行高的 1.35 倍。
4. 动画名称必须为 `marker-sweep`、时长必须为 `0.82s`，动画结束后背景宽度不得为 0。
5. 目标句是计算式、伪代码或较长英文时，可缩短英文高亮短语以适配窄侧栏；
   不得通过缩小整页正文或允许侧栏横向滚动来规避溢出。

## 8 基础审查与对话迭代

每轮初版只执行一次 Basic Review，不拆分 relation/final 两次模型审查。

| 审查层 | 重点 |
| --- | --- |
| 页面 | 溢出、遮挡、层级、密度和阅读路径 |
| 交互 | 可操作性、状态同步、说明与反馈 |
| 内容 | 前后连续、明显事实错误和双语错位 |
| 图形 | 流程、表格、结论是否一致 |

状态统一为：

```text
pass · needs_revision · blocked · awaiting_human
```

失败时：

- Content 问题先修内容。
- Skill 问题先补能力契约。
- Template 问题先修屏型或组件。
- Code/Visual 问题只修受影响页面。
- 不设置固定返工上限；人工满意后才交付。
- 默认最多报告 8 个高价值问题，按严重等级排序。
- 不因 URL 可达性或低价值格式问题阻塞。

## 9 装配与交付

Builder：

```text
live.json.deck
    + CST/TEMPLATE.html
    + Workflow/overrides/lab-v2.css
    + live.json.deck.style_overrides
    → 最终 HTML
```

装配要求：

1. 读取并验证 `live.json` 与其中的 `deck`。
2. 选择对应屏型块。
3. 填主体、左右栏和封面视觉。
4. 替换变量和页码。
5. 清理 `@block`、`@body`、`{{}}` 等标记。
6. 无 `three` 时移除 Three.js 运行时。
7. 注入 Workflow V2.0 全局字体与间距覆盖层。
8. 注入 `style_overrides` 页面专属样式。
9. 在 `Workflow/runs/<task-id>/preview.html` 输出临时交互 HTML。
10. 对临时 HTML 运行静态检查和真实浏览器检查。
11. 执行一次 Basic Review，在对话界面展示临时 HTML 和排序后的问题。
12. 接收人工修改意见并重复，直到制作者满意；截图仅作失败诊断。

交付：

```text
courseware/<课件标题>/
├── content_<课件标题>.md
├── content_<课件标题>.json
└── <课件标题>.html
```

## 10 验收清单

1. 页数与交付 Manifest 一致。
2. 标题、眉标、导语和注释中英文完整。
3. 无重复 `id`、重复交互键或嵌套交互根。
4. 无模板变量、槽位或注释标记残留。
5. 无远程运行时依赖。
6. 首屏和正文无 JS 时可读。
7. 静态初值与交互初始状态一致。
8. 键盘、进度刻度、语言切换和帮助可用。
9. 页面不越过安全区，不遮挡导航。
10. 标题使用默认 serif 字体栈，直接子块满足固定间距。
11. 流程图保持单节点高亮，键盘可切换并同步说明。
12. 标记 `data-flow-highlight="single-fill"` 时无节点描边或焦点外框。
13. 交互 SVG 的活动填充为 `#EFFF54`，命中范围不越过可见图形与文字。
14. 交互节点无论是否选中均无轮廓描边，且不触发 `<title>` 悬浮提示。
15. 时间线节点使用带填充几何图形，不以空心圆表示节点。
16. 终端连续输出时只在面板内部滚动，输入栏始终可见。
17. 封面标题不越界，`.grid-3` 卡片等高。
18. 复杂交互已完成来源检索和对话选型。
19. 交互页面比例达到 70%。
20. 静态和浏览器检查通过，且完成一次 Basic Review。
21. 用户已确认对话界面临时 HTML 可以交付。
22. 交付 Markdown、JSON、HTML 与 SHA-256 一致。
23. 表格交互只有一层外框，详情区无独立边框、圆角、模糊或阴影。
24. 分层 3D 网络的标签安全区、有限环绕、状态提示与无障碍名称在中英文下一致。

# 图表类型选择与可视化设计

用于架构图、神经网络结构图、流程图、模块图和交互拓扑页。先判断读者要完成的任务，再选图；
不要因为主题是“网络”就默认画节点连线图。

## 1 先决定图表用途

| 读者任务 | 优先图表 | 避免 |
| --- | --- | --- |
| 理解原理 | 分层块图、概念流程图、局部放大的示意结构 | 完整算子图、所有神经元同时出现 |
| 调试实现 | 与模型一致的节点/边拓扑，显示输入输出、shape、算子 | 抽象到丢失实际连接或层名 |
| 论文/展示 | 参数化矢量块图，统一形状、标签、配色和尺寸 | 模板拼贴、粒度混杂、装饰性 3D |
| 解释数据流 | 左到右或上到下的箭头链、泳道、Sankey | 无方向散点网络 |
| 比较结构 | 并排同尺度小图或表格 | 不同缩放、不同图例的多图 |
| 展示状态变化 | 状态图、时间线、逐步快照 | 仅用颜色变化而无文字状态 |
| 展示数值趋势 | 折线、柱形、散点等标准统计图 | 用网络节点代替定量坐标 |

核心判断：

1. 邻接关系本身是答案 → 节点—连线图。
2. 层级、模块和顺序是答案 → 分层块图或流程图。
3. 维度、张量和空间结构是答案 → 块体、网格、局部感受野或 3D 体块。
4. 数值大小和趋势是答案 → 标准统计图，不画网络示意。

### 1.1 纳入神经网络分支

```text
读者任务
  → 核心关系是否需要节点/边？
      否 → 流程图、块图、时间轴或统计图
      是 → 是否同时需要模块层级、张量维度或数据流？
            否 → 普通节点—连线图
            是 → 架构图
                  → 是否为神经网络？
                      是 → MLP / CNN / RNN / Transformer / GNN 专用分支
                      否 → 通用系统架构图
```

神经网络分支必须同时说明“用途”和“保真度”：

- 理解原理：允许抽象节点数和内部细节。
- 调试实现：必须忠实保留真实算子、连接、输入输出和 shape。
- 论文展示：允许参数化美化，但结构、标签和维度必须与模型核对。

## 2 神经网络结构图

| 架构 | 推荐表达 | 必须说明 |
| --- | --- | --- |
| MLP / 全连接 | 输入层—隐藏层—输出层的节点连线或分层块 | 层宽、激活、输入输出维度 |
| CNN | 带厚度/面积的层块、卷积核、池化、局部感受野 | 张量 shape、通道数、空间尺寸变化 |
| RNN / LSTM / GRU | 时间展开序列 + 循环边/门控模块 | 时间步、隐藏状态、共享参数 |
| Transformer | 模块容器 + 残差分支 + 注意力/前馈子层 | token 维度、head 数、位置编码、残差路径 |
| 图神经网络 | 节点、边、邻域聚合层 | 图级/节点级/边级任务与消息方向 |

设计规则：

- 主模块通常控制在 5–7 个；需要更多细节时用“总览 → 选择模块 → 局部展开”。
- 不渲染全部神经元。使用“可见节点数 ≠ 实际节点数”的示意，并标注真实规模。
- 层、模块、算子、数据张量使用稳定的形状语义，不要同一形状表示不同概念。
- 每层至少显示角色名；关键层显示输入/输出 shape 或张量维度。
- 所有连接必须有方向；分支和合并处标注条件或张量变化。
- 同一层级保持同一粒度，不把系统模块、层、算子和单个神经元混在同一平面。
- 2D 是默认。只有深度、体积或三维空间关系本身重要时才使用 3D 或透视。

### 2.1 四段式架构图提示词

生成或设计结构图前，先把需求压缩为四段：

1. **主体**：具体模型或模块，例如 CNN 分类器、单个 LSTM 单元、Transformer 编码器。
2. **顺序**：按输入到输出列出层/模块，必须同时给出起点和终点。
3. **标注**：模块名称、关键张量维度、重复次数、分支条件和共享参数。
4. **风格与方向**：扁平技术示意图、统一无衬线标签、左到右或上到下数据流。

推荐句式：

> 画出〔模型〕，含〔输入 → 模块顺序 → 输出〕。标注〔模块名称、张量维度、重复次数和分支条件〕。采用干净扁平的技术示意图，数据从左到右流动。

细化规则：

- 重复结构折叠为带 `×N` 的单一模块，避免把每一层重复铺满。
- 图内文字保持短；推导、公式和解释移到图注或页面正文。
- 使用增量修改，例如“在每个卷积后加批归一化”，不要每次重写整张图。
- 输入 shape、每阶段 shape 和输出 shape 必须形成连续链。
- 若标签过多导致拥挤，拆分总览图和局部模块图，而不是继续缩小字体。

常见错误与修正：

- 模块没有名称或名称错误 → 明确列出真实层名和模块名。
- 张量维度缺失或不连续 → 从输入 shape 开始逐层校验。
- 数据方向含糊 → 给每条主链加箭头并指定唯一阅读方向。
- 文字乱码或过长 → 使用可控 HTML/SVG 文本，必要时缩短并移到图注。
- 重复堆叠过密 → 折叠为 ×N 模块或多面板展开。

## 3 布局与视觉编码

- 选择唯一主阅读方向：从左到右表示常规流水线，从上到下表示阶段或层级。
- 用容器表达包含关系，用箭头表达流动，用并排表达比较；不要三种关系都靠连线表达。
- 颜色映射语义保持稳定：输入、处理、状态、输出、风险各用固定角色色。
- 颜色不能是唯一编码，必须同时提供标签、形状、线型或文字。
- 优先直接标注。只有多种视觉编码无法就近说明时才加图例。
- 标签放在图形外侧或固定标签带，避免覆盖连线、箭头和关键几何。
- 中英文结构图保持相同拓扑；英文变长时调整列宽、换行或标签带，不缩成不可读字号。
- 避免“毛线球”式全连接；用束线、聚合节点、透明分组或局部放大替代。

## 4 动效与交互

- 动效只表达数据流、执行顺序、状态变化或当前路径。
- 选择模块时，图形、读数、说明和面包屑必须同步更新。
- 总览图优先支持选择模块后局部展开；不要一开始把所有细节铺满。
- 自动播放默认关闭，必须可暂停；尊重 `prefers-reduced-motion`。
- 3D 只在空间关系必要且提供旋转、缩放和键盘替代操作时使用。
- 节点高亮、流程推进和悬停状态不得改变布局尺寸。

### 4.1 3D 文件关系网络

当用户明确要求“文件作为节点、连线表示关系、可拖动旋转并常态播放”时：

- 只有文件或关键状态保留大标签；次要流程节点可以只用球体和小型路径带表达顺序，
  避免所有节点都带卡片造成遮挡。
- 球体使用无光照平涂固有色；三维感来自节点位置、透视、有向连线和整体环绕，不添加
  高光、环境光或方向光。
- 默认提供拖拽旋转、滚轮缩放、方向键替代、复位和可暂停自动环绕；系统要求减少
  动态效果时默认关闭自动环绕。
- 至少检查静止初始角度以及旋转后的标签安全区；中英文切换后重新生成标签纹理。
- 低性能或无 WebGL 时保留静态文字拓扑，不得只剩空白画布。
- 表格、SVG 和测验等交互屏应提供两个以上用户可操作控件；例如表格行选择加“全部
  / 只看当前”，SVG 节点选择加“全部 / 聚焦当前”，测验选项加提示控制。

### 4.2 3D 分层神经网络

当工作流或系统过程以 MLP 分层方式呈现时：

- 节点只承担层级位置；文件和层职责放在画布外的固定标签带，避免透视旋转导致卡片
  互相遮挡。
- 使用 `data-network-orbit-range` 限制自动环绕角度，保持输入到输出的主阅读方向；
  拖拽、滚轮、方向键、暂停和复位仍然可用。
- 同层节点使用同一形状和尺寸语义；连线低透明度分组，避免全连接变成“毛线球”。
- 切换语言后同时刷新层标签、状态提示和 canvas `aria-label`。
- 验收至少覆盖静止正视图、环绕最大角度、暂停状态和中英文模式。

## 5 验收

1. 图中每个模块都有明确角色，且没有孤立连线。
2. 输入、输出、方向、层级和关键维度在无 hover 时可见。
3. 主模块数量和文字密度适合单屏阅读。
4. 中英文切换后拓扑、选中状态和读数保持一致。
5. 不依赖颜色区分状态；不使用重叠标签或装饰性阴影遮盖数据。
6. 调试型拓扑允许缩放和局部展开；教学型拓扑允许抽象，但必须明确“示意/实际规模”。
7. 浏览器检查覆盖溢出、连线穿越标签、节点热区、键盘切换和 30 次重复交互。

## 6 工具选择

- 快速概念草图：本项目内联 SVG/HTML，便于离线、双语和交互联动。
- 论文/报告矢量图：参数化生成的方法（NN-SVG、PlotNeuralNet 类）便于统一风格。
- 实际模型调试：Netron 类自动解析工具，忠实展示真实算子和 shape。
- 模板工具：适合快速探索版式，不替代本项目的组件契约、无障碍和交互验收。
